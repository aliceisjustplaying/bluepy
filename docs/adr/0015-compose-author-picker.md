# ADR-0015: Compose has an author picker for multi-account users

When more than one account is logged in, the compose modal exposes a small avatar/dropdown letting the user choose which logged-in account this particular post is sent as. Selecting an author **does not** change the global active account — the next compose opens with the global active account again unless explicitly changed.

Rejected alternative: **author = active account, always**. Multi-account users dashing off a side-account post would have to perform a global account switch (cache clear, re-render, etc.) just to post once. Phanpy-style per-compose author selection is what users expect from a multi-account client.

**Author-switch forks the draft.** `authorDid` is part of `DraftKey` (ADR-0012), not a draft body field. Switching the author in an open compose modal does NOT mutate `authorDid` on the current draft (that would silently rebind a draft the user thought belonged to a different account); instead, `compose.setAuthor(newDid)` creates a fresh draft under the new key `(authorDid: newDid, kind, targetUri?)` with the text/attachments/refs **copied** from the previous draft. The previous draft survives untouched under its own key. Closing and reopening compose for the original account still finds the original draft.

Implementation: the compose store's `Draft` carries `authorDid: string` (mirroring the key, defaults to global active DID when the draft is created via `openDraft`). Submit uses the PDS repo agent for that DID — which means the compose modal needs access to a per-account PDS repo agent, not just the active one. `<SessionProvider>` (ADR-0010) instantiates clients for the active account by default; compose's submit path resolves the chosen author's agent on demand via `getPdsRepoAgentFor(clients, authorDid)` (ADR-0004). Audited writes (`createRecord`, `uploadBlob`) use `pds-repo-direct` mode; authenticated AppView reads for the side account (e.g. fetching the side account's `getPreferences` while composing as them) use `authenticated-active-appview-via-pds` mode with a side-account-scoped `activeAppViewProxyAgent`.
